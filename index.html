1. 核心认知：为什么单靠“好好写 Prompt”还是会翻车？

新手用 AI 写代码最常见的三大痛点：① 改着改着把旧功能改坏；② 同一个报错死循环改 10 轮；③ 用最贵的模型干最杂的活，额度一夜烧光。解决之道不是写更长的提示词，而是引入组织分工与制衡：

【谋】先想后做

架构与方案决策

遇到复杂需求，先让 AI 列出矛盾点和 2~3 个方案，你拍板后再写代码，避免“写一千行再推倒重来”。

【工】极简直出

主力编码与苦力下沉

用均衡主力写代码；把搜文件、读日志、跑测试等重复苦力全部下沉给便宜快速的轻量模型（如 Flash）。

【察】独立挑刺

打破“自写自审”盲区

同一模型写完代码自己检查，往往顺着惯性说“没问题”。关键改动必须拉起隔离窗口或换一家异构模型挑刺。

【史】定容沉淀

只替换，不叠加

项目规则文件（AGENTS.md）严格限制在 80 行以内。规则越短，AI 注意力越集中。

3. 3 分钟在 Antigravity 中安装与实操

前置条件：本机已安装 Python 3（终端输入 python --version 可查看）。在终端运行：

agy plugin install https://github.com/wole278/ai-ops-starter

安装后重启或新开一个 Antigravity 窗口，即刻生效！

前置条件：macOS / Linux 系统通常自带 python3。在终端运行：

agy plugin install https://github.com/wole278/ai-ops-starter

安装后重启或新开一个 Antigravity 窗口，Hooks 会自动调用 python3 守护你的工作区。

如果你下载的是培训离线 ZIP 压缩包：解压后进入 ai-ops-starter 文件夹，运行：

agy plugin install .

Windows 学员也可直接双击文件夹内的 install.bat，Mac/Linux 学员运行 bash install.sh。

苦力下沉 & 异构挑刺 invoke_subagent(Model="flash") & 切异构模型审查 小改动用 Fast 模型，关键代码另开 Tab 让另一家模型 Review 子代理跑测试，主窗口只做决策与代码审查

# 项目 AI 协作约定（严格 ≤80 行） ## 1. 安全底线 - 密钥、密码、个人隐私绝不写入 Git，也不直接粘贴进对话。 - 删除目录、强推代码（force push）、装全局依赖前必须先说明影响并请我确认。 ## 2. 开发纪律 - 最小改动：只改当前需求必需的文件，不顺手重构无关代码。 - 实跑验证：改完必须实际运行测试或构建命令并汇报真实输出，严禁跳过报错。 - 二振熔断：同一个问题连续修 2 次仍失败，立即停手把报错和已排除方案写入 `.agents/handoff/CURRENT_TASK.md`，等我切换模型或拍板，严禁第 3 次盲改。 ## 3. 沟通格式 - 首行标注当前姿态与动作：`> 🧭 【谋 / 工 / 察】 ｜ 判准：<一句话核心动作>` - 复杂任务先给 2~3 个方案再动手；简单任务直接给「结论 + 改动清单 + 测试结果」。
